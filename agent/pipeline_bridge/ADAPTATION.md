# 固定适配边界

GitHub固定19a83f9aeb9d3d02a2a29826b098d49d81570d0e，32个shore_agent文件和两个辅助模块原样保留，不自动拉取更新。提示词、工具schema、拟合目标、候选排序和科研循环不重写。配置对照GitHub E8 R04有噪声批次，e4配置控制原Agent的提交门槛，不修改实训环境。

仅在适配层绑定积分和导出函数：numerics._integrate、symbolic_regression._short_rollout、submission.export_submission。前两者统一调用官方rift.rollout，后者转换为正式全对象加速度接口并通过真实Console保存/提交。短轨迹检查沿用原采样终点、观测比较及0.4秒时限；RHS计数使用官方固定积分的实际次数。

原仓库探针方程没有输出背景运动方程。无背景依赖的探针方程，背景填零加速度不影响探针预测；依赖源位置且公开背景初速全为零时，导出明确的静止源候选。需要运动源轨迹却没有源运动方程的候选明确报background_model_required，不将已观测背景轨迹插入预测，也不擅自新增背景推断算法。此项是不能无损转换的候选类别限制，必须单列其影响，不能据此声称完全等价或保证相同成功率。

官方文件解压后全部只读，固定哈希保存在agent/official-files-original.json。所有开发、缓存、依赖、日志和实验产物位于agent内。正式冻结副本不包含旧实验答案或测试公式。

OT01登记三轮独立重复，每轮六公开宇宙，每轮每界只尝试一次；不按成绩重试，不拼接最高分。成功定义为完整固定用例测评且总分>=90，保留全部失败和不完整结果。GitHub R04仅一轮、2/6成功；当前main另含测评后去重补丁，尚不能保证达到相同成功率。

正式保存/提交由独立序列化包装器在原Runtime选定配对且通过原检查后执行。被拒绝的草稿回滚到此前选定配对；单纯导出检查不会覆盖官方草稿。该边界已用真实Console及失败草稿回归检查验证。

新批次OT02按用户跨聊天资源分配，仅使用8000，串行运行六公开宇宙一轮。原OT01保留所有已开始的13场和未领取mission被用户更新取消的5个槽位，不混入新版统计。R05实测代码882315c与最新main的三个科研文件存在后续差异，因此不能将R05五界>=90当作当前main已验证的成功率。
